# ADR-0000：ADR 模板（这是模板，不是决策记录）

- **状态**：模板
- **日期**：2026-11-09
- **决策者**：你自己
- **相关**：无

## 1. 背景与问题

用 3~5 句话回答：我们当时面临什么问题？有什么约束（团队、时间、成本、已有技术栈）？
不要写"因为新技术很酷"。

## 2. 决策

用 1~2 句话写清楚**决定了什么**。用陈述句，不用"我们考虑……"。

> 例：采用 SQLite 作为持久化存储，通过 SQLAlchemy 访问，repository 层隔离具体数据库。

## 3. 备选方案与对比

| 方案 | 优点 | 缺点 | 为什么没选 |
| --- | --- | --- | --- |
| A | | | |
| B | | | |

**没有一个方案是全优的。如果写不出缺点，说明你还没想清楚。**

## 4. 后果（这是最重要的一节）

- **正面**：我们获得了什么？
- **负面**：我们付出了什么代价？以后会遇到什么麻烦？
- **风险**：什么情况下这个决策会失效？失效时怎么办？

## 5. 验证方式

我们怎么知道这个决策是对的？

> 例：压测达到 200 QPS / P99 < 150ms，且不需要改 api 层代码。

## 6. 何时该重新评估

> 例：当日活超过 5000，或出现多实例部署需求时，重新评估是否换 PostgreSQL。

## 写作要求（给自己立的规矩）

1. 一份 ADR 不超过 1 页，超过说明你把它写成了设计文档。
2. **必须写"代价"**。只写优点的 ADR 等于没写。
3. ADR 一旦写下就不要改内容，被推翻时新增一份并标注 `取代 ADR-00X`。
4. 一个决策一份，不要把三个决策写在一起。
